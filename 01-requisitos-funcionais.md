# ⚙️ Requisitos Funcionais

## O que são?

Os **requisitos funcionais (RF)** descrevem o que o sistema deve fazer: suas funções, serviços e comportamentos diante das ações dos usuários ou de outros sistemas.

Eles ajudam a definir quais funcionalidades precisam ser desenvolvidas.

## Exemplos

Em um sistema de delivery:

- **RF01:** O sistema deve permitir que o cliente crie uma conta.
- **RF02:** O sistema deve permitir que o cliente entre com suas credenciais.
- **RF03:** O sistema deve exibir os produtos disponíveis no cardápio.
- **RF04:** O sistema deve permitir que o cliente adicione produtos ao carrinho.
- **RF05:** O sistema deve calcular o valor total do pedido.
- **RF06:** O sistema deve permitir que o cliente finalize um pedido.
- **RF07:** O sistema deve exibir o status do pedido.

## Como escrever um requisito funcional?

Prefira uma frase clara, específica e que possa ser verificada.

**Modelo:**

> RF01 — O sistema deve permitir que [ator] realize [ação].

Exemplo:

> RF01 — O sistema deve permitir que o cliente consulte o cardápio.

## Boas práticas

- Use identificadores únicos, como RF01, RF02 e RF03.
- Descreva uma funcionalidade por requisito sempre que possível.
- Evite frases vagas, como “o sistema deve ser bom”.
- Escreva de forma que seja possível verificar se a funcionalidade foi implementada.
- Confirme os requisitos com as pessoas interessadas no sistema.

## Checklist

- [ ] O requisito descreve uma função ou comportamento?
- [ ] Está escrito de forma clara?
- [ ] É possível verificar se foi atendido?
- [ ] Está identificado de forma única?
