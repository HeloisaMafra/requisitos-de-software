# 📝 Exercícios — Requisitos de Software

Tente responder antes de consultar o gabarito.

## Parte 1 — Classifique os requisitos

Classifique cada item como **RF (Requisito Funcional)** ou **RNF (Requisito Não Funcional)**.

1. O sistema deve permitir que o usuário redefina sua senha.
2. A página de pesquisa deve apresentar os resultados em até 3 segundos nas condições de teste definidas.
3. O sistema deve gerar um comprovante após a conclusão da compra.
4. O sistema deve restringir o acesso aos dados administrativos a usuários autorizados.
5. O cliente deve poder cancelar um pedido antes de ele entrar em preparação.
6. A interface deve funcionar nos dispositivos móveis definidos no escopo do projeto.

## Parte 2 — Melhore os requisitos

Reescreva os requisitos vagos abaixo para que possam ser avaliados.

1. O sistema deve ser rápido.
2. O sistema deve ser seguro.
3. O sistema deve ser fácil de usar.

**Dica:** defina uma condição observável ou uma forma de avaliação. Não existe uma única resposta correta; os critérios precisam fazer sentido para o contexto.

## Parte 3 — Crie seus próprios requisitos

Imagine um aplicativo de biblioteca. Escreva:

- 3 requisitos funcionais.
- 2 requisitos não funcionais.
- Um identificador para cada requisito, como RF01 e RNF01.

## ✅ Gabarito — Parte 1

1. **RF** — oferece a função de redefinição de senha.
2. **RNF** — estabelece uma meta de desempenho.
3. **RF** — descreve a geração de um comprovante.
4. **RNF** — define uma condição de segurança. (O mecanismo de controle de acesso também pode envolver funcionalidades específicas.)
5. **RF** — descreve a função de cancelar um pedido sob determinada condição.
6. **RNF** — define uma condição de compatibilidade.

## 💡 Exemplos de respostas — Parte 2

As metas abaixo são apenas exemplos; devem ser definidas de acordo com as necessidades do sistema.

- **Rápido:** “Nas condições de teste acordadas, 95% das pesquisas devem responder em até 2 segundos.”
- **Seguro:** “Somente usuários autenticados e autorizados podem acessar a área administrativa.”
- **Fácil de usar:** “Em um teste de usabilidade com o público definido, pelo menos 8 de cada 10 participantes devem concluir o cadastro sem ajuda.”

## 📌 Lembrete

Um requisito bem escrito deve ser claro, relevante e, sempre que possível, verificável. Os requisitos precisam ser validados com as pessoas envolvidas no projeto.
